# Ralph progress: Automatos Play pilot (PRD-001)

## Patterns
<!-- Reusable patterns for later sessions. Keep this short and current. -->
- Nothing runs locally. Pin dependency versions with `npm view <pkg> version` and edit package.json by hand. CI is the gate.
- The backend is reached only through app/api/* routes; the browser uses lib/client/api.ts.
- The mascot files in public/auto/ are git-ignored and absent in CI: always degrade to the placeholder.
- Vitest globals are OFF: import describe/it/expect/vi from "vitest" in every test. tests/setup.ts loads jest-dom matchers and RTL cleanup. Tests live in tests/ (or next to code) as *.test.ts(x); the @/* alias maps to the repo root.
- vitest 5 needs vite as a peer: vite is pinned in devDependencies. Keep vite, vitest and @vitejs/plugin-react moving together.
- ESLint is flat config (eslint.config.mjs) with FlatCompat over next/core-web-vitals + next/typescript; `npm run lint` is `eslint .`. docs/, skills/, scripts/, public/ are ignored.
- next-env.d.ts is committed (classic two references) so `tsc --noEmit` works before any `next build`.
- Colours, type, spacing, radii, shadows: app/theme.css only. tests/theme.test.ts fails on any hex/rgb()/hsl() in another .css under app/ or components/. Add a token instead.
- Component styles are CSS Modules next to the component (vitest returns a proxy for them; tests query by role, never by class). Breakpoints: phone < 768 px (sidebar and page header hide, phone bars show); mascot column hides < 1024 px.
- Pages render inside AppShell (from app/layout.tsx). A page with Auto uses PageColumns({mascot: <MascotColumn><AutoMascot state=… /></MascotColumn>}) and PageHeader for the 68 px title row. AutoMascot carries its own caption (captionFor in lib/mascot/media.ts; override with caption/detail). Tests that render AppShell must vi.mock("next/navigation") for usePathname.
- Proxy routes import from lib/server/backend.ts (getBackendUrl, jsonError, backendUnreachable, rejectCrossSite, workspaceHeader, readJsonObject). Every route calls rejectCrossSite first (no login, so CSRF matters): it 403s a Host outside localhost/127.0.0.1/[::1] + PLAY_ALLOWED_HOSTS (DNS rebinding), Sec-Fetch-Site other than same-origin/none, and 415s a request body not sent as application/json. lib/client/api.ts must send Content-Type: application/json on every request with a body. Route tests start with `// @vitest-environment node` (real undici Request/Response/ReadableStream), stub fetch with vi.stubGlobal and the env with vi.stubEnv, and unstub in afterEach.
- Every proxy route is a few lines over lib/server/forward.ts: `forwardToBackend(request, {path, query?, jsonBody?, accept?})`. `query` is an allowlist of keys (default none: the backend reads ?workspace_id= when no header is sent). Dynamic [id] params go through `pathId(raw)` (null -> `invalidId()` 400) before they touch a backend path. Next 15 handler context is `{ params: Promise<{ id: string }> }`.
- The browser uses `api` from lib/client/api.ts (types and boundary parsers in lib/client/types.ts, camelCase). Tests build their own with `createApiClient(vi.fn<Fetch>(...))`. It sends Content-Type: application/json on every non-GET (even bodyless: Next may give a route a non-null body, and rejectCrossSite 415s untyped bodies). Failures throw ApiError(status, friendly message); status 502 = Automatos isn't running, 0 = Play's own server didn't answer. listDeliverables returns {success:false, error} instead of throwing.
- tests/server/boundary.test.ts fails if anything outside app/api imports lib/server, or if the admin key name appears in code/config. Don't write that key name in code or tests (build it by join if you must).
- Stream events: `parseChunk(state, bytes)` / `finishParse(state)` from lib/stream/parse.ts (pure: state in, state out), or `readStreamEvents(body)` for a fetch body. Events are the `StreamEvent` union in lib/stream/types.ts (camelCase; wire names kept for limit_reached, attachment_unavailable, withdraw_offer). Stream tests replay tests/fixtures/*.txt through `fixtureEvents(name)` / `parseChunks` in tests/stream/helpers.ts and run in `// @vitest-environment node`. The turn's receipts come twice (a tool-data frame, then the receipts event): read the receipts event only.
- Mascot: `mascotReducer(state, event)` from lib/mascot/reducer.ts takes StreamEvents and ClientEvents (lib/mascot/types.ts). `state.mascot` is the target state; the player owns clip boundaries, hold time and timers, and dispatches `{type:"clip-ended", state}` when a one-shot clip ends. Tool names live only in lib/mascot/tools.ts (tests/mascot/tools.test.ts enforces it). Replay mascot sequences with `sequence(events)` / `replay(events)` in tests/mascot/helpers.ts.
- Mascot player: `<AutoMascot state={mascot.mascot} onClipEnded={(state) => dispatch({type: "clip-ended", state})} />` (components/mascot/). It queues to the clip boundary itself (lib/mascot/player.ts), and with no video (reduced motion, missing files, SSR) shows the target at once and ends one-shots on a 5 s timer. Component tests fire img load/error and video timeupdate/ended by hand (define `duration`/`currentTime` on the element); the files are never in CI.
- Chat screen: components/chat/ (ChatScreen is the client root: no chatId -> ChatView, a chatId -> StoredChat, which loads and then renders ChatView; app/page.tsx reads ?chat= with chatParam and keys ChatScreen by it). Labels for tool lines and receipts are pure in lib/chat/labels.ts (words from toolActivity or the readable tool name, never a quoted tool name); the caption under Auto in lib/chat/caption.ts. Model text goes only through components/chat/Markdown.tsx (skipHtml, images as alt text: reuse it for Deliverable content in US-012). Layout switches with `useMediaQuery(MASCOT_COLUMN_HIDDEN, false)` from hooks/useMediaPreferences.ts. Component tests: `render(<ChatScreen client={createApiClient(mockChatFetch([...]))} />)`, userEvent.setup(), `{Enter}` to send, `waitFor` any fetch-count assertion (the client awaits /api/workspace first), and end each test by awaiting the Send button so the turn finishes inside the test.
- Chat: `useChatTurn({client?})` from hooks/useChatTurn.ts is the only thing that sends a chat turn. It owns the mascot reducer (`mascot`, `dispatchMascot`), the message model (`ChatMessage` in lib/chat/types.ts; pure updates in lib/chat/turn.ts) and stop(). `send()` resolves when the turn ends and never rejects. Hook tests drive it with `mockChatFetch([...answers])` + `createApiClient` from tests/chat/helpers.ts (fixtureAnswer, hangingAnswer for a turn that waits until stop, lastReply); start async sends with a sync `act(() => { pending = send(...) })`, `waitFor` the text, then `await act(async () => { await stop(); await pending; })`.
- Addresses: a conversation opens at `chatHref(id)` = /?chat=<id> (lib/chat/params.ts). Saved messages -> ChatMessage with `fromStoredMessages` (lib/chat/stored.ts). For one request as render state use `useLoad(load, friendlySentence, logLabel)` from hooks/useLoad.ts (memoise load with useCallback; Loaded<T> = loading | ready{value} | failed{error, retry}). After anything that changes the conversation list call `announceChatsChanged()` (lib/client/chat-events.ts): the sidebar's Recent list (LiveShell + useRecentChats) reloads. `mockChatFetch(answers, routes)` answers extra routes by path (`{"/api/chat/history": () => Response.json([...])}`). Pin "now" in date tests with local `new Date(y, m, d, h)` so they pass in any time zone.
- Deliverables: type words/colours come from lib/deliverables/shelf.ts (kindOf, typeLabel, shelfDate) and components/deliverables/TypeBadge.tsx + kinds.module.css (`.kindTile` is the type-coloured ground). Thumbnails: `useThumbnail(client, id)` (object URL, revoked on unmount; null on 404). Component tests mock fetch with `mockShelfFetch(list, thumbnail?)` from tests/deliverables/helpers.ts (`row()`, `listBody()`, `listCalls()`); jsdom has no URL.createObjectURL, so stub it with defineProperty and restore it (see stubObjectUrls in ShelfScreen.test.tsx). A list's success:false `error` is raw exception text: log it, never show it.
- Deliverable files: the browser never names a workspace path. `app/api/deliverables/[id]/file` reads the row's own preview_url and forwards it only if `rawFilePath()` (lib/deliverables/file.ts) accepts it (/api/workspaces/<ws>/files/raw?path=…). Images load through `api.deliverableFile(id)` -> object URL (hooks/useDeliverableImage.ts); downloads are a plain `<a href={deliverableFileHref(id)} download>`. Decide how to show content with `contentView()` (lib/deliverables/detail.ts) by file_type, never by `content !== null` (binary files come back as UTF-8 noise). Detail tests: `mockDetailFetch(detail, file?)` + `detailBody(row)` + `stubObjectUrls` in tests/deliverables/helpers.ts.
- A new chat with words waiting: link to `draftHref(text)` (/?draft=…); app/page.tsx passes `draftParam` to ChatScreen -> ChatView `initialDraft` -> MessageBox.
- hello: `claimFirstOpen()` (lib/mascot/session.ts) is true once per browser session; ChatView dispatches app-open on it. hello is a one-shot that holds Auto for a clip, so any component test that checks Auto's state after a send sets `window.sessionStorage.setItem(HELLO_KEY, "1")` in beforeEach. An empty chat has no mascot column: Auto is big in the FirstOpenHero (region "Say hello"); the column (or the phone row) appears after the first send.
- Backend asleep: LiveShell asks `useBackendStatus(client, recheckMs)` (GET /api/workspace; 502 -> asleep, re-asked every RECHECK_MS, or `check()`); while asleep the whole window is AsleepScreen and the pages unmount. useRecentChats waits for `ready`. Shell tests that render LiveShell must answer /api/workspace (mockChatFetch does).
- Timers for the mascot live in hooks, never the reducer: `useIdleTimeout(onIdle, onActive, ms)` (window input events) drives idle-timeout / wake. Components that own such a timer take an `idleMs`/`recheckMs`/`refreshMs` prop so tests run on real timers in milliseconds.
- Accessibility guards (tests/a11y/): the focus ring is `outline: var(--focus-outline)` + `outline-offset: var(--focus-offset)` in globals :focus-visible; a rule that sets `outline: none` must draw `box-shadow: var(--focus-…)` itself (or be in OWN_FOCUS with a reason). Every `<button|Link|a|input|textarea>` in components/ needs `className={styles.x}` whose rule sets `min-height: var(--tap-min)` (inline text links are allowlisted in UNSIZED). No width/min-width/flex/grid-columns/custom-property px value over 390 outside `@media (min-width…)`. A text colour on a new ground: add `--color-fg on --color-bg` to theme.css's header list (contrast.test.ts checks 4.5:1). Never use tabIndex. tests/a11y/css.ts has the small CSS reader (cssRules, declarations, themeTokens, resolveTokens, pxLengths).
- Stream fixtures start with a `# SYNTHETIC fixture` or `# RECORDED` header (tests/stream/fixtures.test.ts checks it); how to record real ones is docs/RUN-CHECKLIST.md. Setup docs are guarded by tests/setup-docs.test.ts: change README, .env.example and docker-compose.yml together.
