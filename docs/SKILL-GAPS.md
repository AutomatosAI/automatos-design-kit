# Skill gaps

Where `skills/build-automatos-interface/` or the mocks were wrong, missing or unclear during the pilot build, and what was done. The core wins: the skill is fixed to match it.

| Story | Gap | What was done |
|---|---|---|
| US-004 | `endpoints.md` said `GET /api/deliverables/{id}` returns "one Deliverable". It returns `{success, deliverable}` and 404s a missing id (`api/deliverables.py:108-128`). | Skill fixed. `lib/client/api.ts` `getDeliverable` unwraps `deliverable`. |
| US-004 | `endpoints.md` didn't say `preview_url` / `content_url` are backend-relative paths (`/api/workspaces/{ws}/files/raw?path=…`) for workspace files, so the browser can't load them. | Skill fixed. Play has no proxy for workspace files yet: US-012 must either add one (`/api/workspaces/[ws]/files/raw` through `forwardToBackend`) or treat those URLs as unavailable. |
| US-004 | An `<img src>` can't send `X-Workspace-ID`, so the thumbnail route can't be used as a plain image URL. | `api.deliverableThumbnail(id)` fetches the bytes with the header and returns a Blob (null on 404); the card makes an object URL. |
| US-004 | The skill says the backend falls back to `DEFAULT_WORKSPACE_ID` without `X-Workspace-ID`; it doesn't say it reads `?workspace_id=` first (`core/auth/hybrid.py:77`). | The proxy forwards only the query keys each route allows (`ForwardOptions.query`), so a stray `workspace_id` never reaches the backend. |
| US-005 | `chat-stream.md` said `agent-info` puts `agent` at the top level. The core sends `d:{"type": {"type": "agent-info", "agent": {…}}}`: `service.py` passes the whole dict to `format_aisdk_data` as the event type, so Studio's own check never matches. | Skill fixed. `lib/stream/data-events.ts` unwraps an object-valued `type` and also accepts the flat shape. A core bug, not worked around silently: worth a one-line fix in `automatos-ai` (flag to the maintainer; Play needs no core change). |
| US-005 | The skill didn't say the turn's receipts arrive twice: first on a `tool-data` frame (`data.receipts`), then as the `receipts` frame (`receipts.py` `receipts_frames`), and that the frame is sent on every finished turn, even with an empty list. It also left out the `above` field. | Skill fixed. The parser emits both; US-008 must take receipts from the `receipts` event only. `ReceiptsEvent.above` carries the lines. |
| US-005 | The PRD asks the fixture tests to split chunks inside a multi-byte character, but the core's `json.dumps` escapes all non-ASCII, so a byte-faithful fixture is pure ASCII. | Fixtures stay byte-faithful (ASCII, `\uXXXX`). The chunk tests also run a raw-UTF-8 re-encoding of each fixture (`rawUtf8Variant` in `tests/stream/helpers.ts`). Skill notes the ASCII wire. |
| US-006 | `mascot-states.md` gave `generate_document` as a **working** example, but its reading pattern (`/document\|knowledge\|memor\|semantic\|graph/`) matches it, and also matches other writes in `orchestrator/modules/tools/` (`platform_upload_document`, `platform_delete_document`, `platform_reprocess_document`, `platform_store_memory`, `platform_delete_memory`, `platform_codegraph_index`, `platform_codegraph_reindex`, `platform_codegraph_set_auto_reindex`). | Skill fixed: an exact **working** list, checked before the patterns. `lib/mascot/tools.ts` `WORKING_TOOLS`. |
| US-006 | The skill didn't say where Auto goes when a tool ends successfully, or when a turn finishes with Auto still thinking. The PRD's example sequence (`thinking → working → idle → celebrate`) implies `idle`. | Skill fixed: `tool-end` goes back to a tool still running, else `idle`; `finish` from thinking/working/searching/reading goes to `idle`. |
| US-007 | `mascot-states.md` said to swap on `timeupdate` within 80 ms of the end "because looping clips don't fire `ended`". Browsers fire `timeupdate` every 15-250 ms (HTML spec), so with the `loop` attribute the 80 ms window is missed on most clips and the queued state never shows. | Skill fixed: loop clips play without `loop`; at the boundary (`timeupdate` within 80 ms, or `ended` as the backstop) the player swaps or restarts the clip itself. `lib/mascot/player.ts` `clipBoundary`, `hooks/useMascotPlayer.ts`. |
